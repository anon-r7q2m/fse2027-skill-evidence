# Original skill implementations and one archived consuming chain

This September 30 supplement improves inspection of existing Agent2Skill
development. It is an archival publication, not a new experiment. No package,
agent, model, container, benchmark, or grader is executed during preparation
or by the checker below.

## Nine-class implementation coverage

`catalog/{G,R,C,S,P,F,L,Q,A}/original_package/` contains all 25 unchanged
selected files (18 Python modules and seven original `package.json` files),
255,437 bytes, at the versions named in the existing development catalog.
Each directory also contains its existing public ABI/profile. The nine classes
remain a survivor catalog, with eight given-target development classes and
one model-selected target after same-source development, not an extraction
success denominator.

[CATALOG_INSPECTION.json](CATALOG_INSPECTION.json) is a **new inspection
inventory**, not an original generation or delivery manifest. G and R have no
original `package.json`; none is reconstructed. File-map digests identify the
unchanged selected versions. They do not make the packages interchangeable,
close their host dependencies, or establish source equivalence. G's original
`SOURCE_METADATA_INVALID` remains unresolved. Most qualification and host
entries retain their existing `REPORTED_ONLY` status. L/P capacity stage
projections remain distinct from qualification.

## The existing A → P → published object chain

`aider_ap/records/` contains an allowlisted slice of the corrected public AP
entry originally executed on September 20. The project-authored magnitude
fixture and all architect/editor responses were predetermined. The string
`PRIVATE_TO_ARCHITECT_ISSUE_CARD_MARKER` is an artificial public isolation
marker, not a private task or credential.

Read these stages in order:

1. A's three `architect/*/{input,output,invocation}.json` triples show its
   request, nonempty advice, fresh-history handoff and final editor receipt.
2. `editor_begin.json` and `P2/01_begin_samples/input.json` receive exactly the
   handoff's advice, including its two leading spaces and two trailing LFs.
   P is the original SEARCH/REPLACE editor, not historical `P_sel`.
3. P's four callback triples record sample requests, parsing, admission,
   normalization and selection. The predetermined responses produce three
   `return -value` candidates and one `return 1` candidate; all four are
   admitted. Two distinct normalized keys and trees yield three winning votes.
4. `materialization/1..4/` contains actual before/after files and materialization
   receipts. `snapshots/capture_002/` retains the exact selected patch and
   original capture manifest. The selected file has a leading blank line;
   it is preserved, not silently normalized away.
5. `endpoints.json` links selection and the unchanged captured tree to
   publication. A's final callback acknowledges that same tree. Original
   worker, cleanup and parent-wait receipts are included. The recorded account
   is one architect and four editor responses; its 500 input / 100 output
   tokens are **synthetic RecordedProvider usage**, not measured model cost.

The exact selected tree is
`10fcce7274e833719a050f92f7daa09302ac60d9`. Original A/P seals and unchanged
modules support package identity. `host_source/*.py.txt` contains inspection

## Check existing bindings

From any directory, run `python3 -B reuse_depth/check_archival_bindings.py`
with a path to this extracted artifact. The standard-library checker verifies
file identities, callback state continuity, worker bindings, exact handoff
consumption, normalized-key receipts, actual materialized Git objects, the
captured patch/tree, publication and A's terminal. It performs no imports of
study code and no process execution. A consistent archive is not a new
behavioral test, a correctness oracle or an attestation of provider identity.

The recovery directly supports only the executed nonempty, admitted K4,
completed-editor branch. The initial failed ordinary entry's old prepend code,
observation roster and complete wire are unavailable; its diagnosis stays
report-based. AP does not contain that ordinary Delivery roster. Complete
provider traffic is deliberately excluded, so per-request readonly/marker
properties remain source/report claims rather than raw-wire observations.
The finite qualification suites are not recovered here. There is no new
live-model utility, benchmark score, comparative-method result, or full donor
equivalence claim.

## Publication and license boundary

[PRIMARY_CONTINUATION_OBSERVATION.json](PRIMARY_CONTINUATION_OBSERVATION.json)
is a post-hoc projection of already released outcomes and stage records.
L/Ln solve 5/7 and P/Pn 8/10, whereas LP/LnPn solve 13/4. Four of Ln's seven
successful primary paths have `NO_LOCALIZATION` and continue through ordinary
editing. LnPn reaches its strict pool on 5/16 paths, against LP's 15/16;
ten LnPn paths stop at unsent local input admission and one at the Python
file-domain condition. These are whole-policy observations; algorithm,
continuation and realized-cost differences preclude a synergy or causal-gate
conclusion. No new fallback's score is inferred and no grade is rerun.

[PROVENANCE.json](PROVENANCE.json) distinguishes exact original bytes from
the small number of path projections and gives original/publication hashes.
Path projections replace the author-machine project root with `<PROJECT_ROOT>`;
task text, package code, candidate files and patch bytes are unchanged. No
private annotations, hidden assessment inputs, original provider requests,
benchmark patches or raw grading logs are included.

Project-authored code/documents retain the root MIT grant. Donor-derived
content retains the six pinned donor notices under `licenses/`; Aider is
Apache-2.0 and the other five supplied notices are MIT. Existing source slices
and their notices remain in their original artifact directories.
