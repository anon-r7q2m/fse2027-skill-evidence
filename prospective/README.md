# Prospective native-workflow study

This study fixed two public framework versions and four static diagnostic
opportunities before target behavior execution. Two fresh coding-agent contexts
per framework received either ordinary review instructions or additional
consumer/object/property/input-path guidance. Both could trace source, inspect
contracts, and construct direct checks. Each could submit at most one prediction, two triggers, two legal controls
and one local patch; all four submitted one prediction. This cap prevents
interpreting equal counts as equal general diagnostic productivity. The ordinary contexts were not restricted
to a deliberately weak test strategy.

The fourteen inputs (six triggers, eight controls) ran on original source and
two separately patched copies per family, giving 42 native workflow calls.
These are four related predictions in two purposively selected frameworks,
not 42 independent samples or benchmark scores. Model responses are finite
scripts; full native agent loops, local executors and consumers run normally.
No paid model, Docker or benchmark grader is involved.

## Results and qualifications

| Framework / context | Observed mechanism | Frozen intervention |
| --- | --- | --- |
| smolagents / guided | Raw-text identifier repair changes string literals; the checker correctly rejects the corrupted value | Rename AST name spans while retaining literal data and required variable repair |
| smolagents / ordinary | Python optimization removes a registered checker call inside an assertion, accepting the invalid candidate | Explicitly evaluate the checker and retain native retry/acceptance |
| AutoGen / ordinary | Configuration round trip loses the eligible-source filter, allowing premature team termination | Serialize and restore the filter |
| AutoGen / guided | Generated/executed events appear in the stream but not the response used by event-inclusive counting, causing an extra execution | Forward the same events to the native consumer |

Every own intervention produces its predicted local change; the other
prediction's trigger remains. All eight legal inputs retain their declared
behavior on the corresponding three versions. The optimized valid-answer
control retains correct output even though the original still skips its
checker; it does not prove a satisfied checking contract. No fixture-wiring
correction was used.

The first smolagents case is preprocessing damage, not a checker making a
wrong judgment about the value it receives. Its documented maximum-step
fallback is legitimate. The second is conditional on optimization, not a
default-configuration claim or certification that all optimized execution is
supported. Neither AutoGen termination nor an exit-zero observation is a
task-success certificate. Patches are local interventions, not upstream-
accepted, globally complete or proven minimal fixes.

Both contexts found different supported mechanisms. This supplies native
workflow knowledge but no observed guidance advantage in finding counts.
The contexts inherit one default model configuration, whose exact server
version is not independently attested. Four contexts, shared schema, disclosed
prior familiarity, synthetic inputs and two purposefully selected families cannot establish
diagnostic superiority, equivalence, prevalence or developer benefit. Actual
model-driven task outcomes remain unmeasured.

## Inspect

- `protocol/PROTOCOL.md`, selection/acquisition and input-freeze records: original design and chronology.
- `diagnostics/`: exact common/guidance packets, predictions, public obligations, scripts, patches and exposure disclosures.
- [Independent final adjudication](protocol/ADJUDICATION.md) and [all item-level judgments](protocol/G4_ADJUDICATION.json): two supported-with-scope and two supported mechanisms; no behavior refutation or unresolved observation.
- `protocol/*static_qualification.md`: independent pre-execution contract and entry review, with limited label concealment.
- `observed/runs/`: all 42 native observations, explicit launch environments, process receipts and output logs.
- `observed/native_observations.json`: a convenience reduction, not a replacement for the raw facts or an adjudication oracle.
- `protocol/QUALIFICATION_PROJECTION_BINDING.json`: after-execution verification that the label-concealed qualification JSON retained every semantic field of the original frozen prediction; this later verification is not represented as a new pre-execution seal.
- `protocol/EXPLANATORY_NOTE.md`: a familiar information-loss condition, explicitly not a novel theory or an experimental result.

Author filesystem roots are replaced by `/STUDY_ROOT` and `/RESEARCH_ROOT`.
`PUBLICATION_TRANSFORMS.json` records original and published digests. Public
seals identify their derived public-file hashes and retain the original
pre-execution hashes separately. Only paths and these explicitly marked
publication fields change; executable fixtures, patches, inputs and oracles
are unchanged. Original timestamps refer to original events, not to the
generation of anonymized copies.

## Reproduce

Use CPython 3.12 on Linux with Git. Source archives are included unchanged:
smolagents `227ef5e49ddd82339295939072f0223249aa8d38` and AutoGen
`027ecf0a379bcc1d09956d46d12d44a3ad9cee14`. Preparation checks their archive
digests and extracts them into a **new** workspace. Dependency installation
requires PyPI access; target replay itself uses no network or credentials.
The resolved runtime dependencies are pinned in `requirements.txt`; pip's
isolated build dependencies follow the pinned projects' build requirements.

From this artifact's root:

```sh
python3.12 prospective/prepare.py --workspace /tmp/native-study --install
/tmp/native-study/venv/bin/python -B prospective/run_matrix.py \
  --study-root /tmp/native-study \
  --protocol-root prospective/protocol \
  --output-root /tmp/native-study-replay
```

Both directories must be new. Keep the output separate from `observed/`.
The finite scripts execute trusted print/assignment/check/exit statements in
owned workspaces, with at most 120 seconds per outer call. Collection status
`OBSERVED` is not a confirmation verdict. Compare each record with its frozen
prediction, including native result state, checker calls, producer facts,
termination, call-shape failures and all legal controls. A missing dependency,
unexpected script call or exhausted script is inconclusive, never success.
